Autonomous Kit architecture

The shape of it

Plain Node modules under scripts/, with no runtime dependencies, plus thin adapters for each tool. Every module is pure enough to test without a repository: the expensive I/O is at the edges, and the decisions are functions over data the caller supplies.

Module Responsibility
scripts/autonomous-config.mjs Reads autonomous.config.json and merges it over the defaults. Everything project-specific enters here and nowhere else. A malformed file degrades to defaults with a note rather than throwing, because every caller is a check or a hook that must not be the reason work stops. The default protected paths are the autonomous kit's own files.
scripts/work.mjs The queue: schema, approval, dependencies and cycles, evidence, and the status view. Also the command surface — status, check, no-yield, brief, quiet, config. In the package's own folder, which has no queue, the queue commands say so and exit zero.
scripts/live-state.mjs Checks work/CHECKPOINT.md against the items: the objective names a real item, every open item has a queue row, and the part above the log stays small. Also the decision about whether there is still approved work to do.
scripts/lane-guard.mjs Which changed paths, in the working tree and in commits not yet pushed upstream, belong to the support lane; whether the instructions still name a live milestone, whether their references still resolve, whether every document is mapped and every accepted task is in the changelog, plus the privacy and commit-identity scans.
scripts/documentation.mjs Fingerprints a configured set of sources, compares them with the stamp on a living document, and rewrites that one stamp line on request. The only writer in the module, and it never touches prose.
scripts/verify.mjs Runs a command between two hashes of the source tree and writes a receipt. A receipt whose tree moved during the run is not evidence.
scripts/context-hook.mjs The lifecycle adapter: reads the checkpoint and the items and returns a bounded block of recovery context. Always writes one JSON object and always exits zero. The Claude Code SessionStart hook prints the same render.
bin/autonomous-install.mjs Copies the autonomous kit verbatim, renders the scaffold in template/ with the answers, merges rather than replaces package.json, .gitignore, and an existing .claude/settings.json (after a backup), and stamps the living documents by running the installed copy as its own process. It works out the whole plan before writing, so a dry run reports what a real run writes, and names the protected files it writes in a support-lane record under work/messages/, so the project's check passes at once. It writes the project's work state (the coordination files and the setup task) and the living documents only on a first install. Run again, it updates: the answers come from the project's config, the config is merged, and --force replaces only a file whose bytes still match an install record's pin. It refuses a project on version 1 of the autonomous kit.
bin/autonomous-uninstall.mjs Removes what the install records under work/messages/ say the installer wrote, while the bytes still match; puts back what --force replaced; takes only the kit's part out of the files it merged into; and leaves changed files alone.

Decisions worth knowing

Each fact is written once. A task's status, owner, and files live only in its item under work/items/. The coordinator's queue and dated log live in work/CHECKPOINT.md, whose rows name item ids rather than copying them. Version 1 kept the same facts in four files and a validator checked that the copies agreed.

One configuration file, read at the edge. The alternative, constants per module, would tie the scripts to one project. Defaults are generous enough that a three-line config works.

Checks report everything, not the first failure. The task checks and the autonomous kit checks are independent lanes. Returning early let one incomplete task hide every other problem, and check is often the only thing a session runs.

Hooks fail open, checks fail closed. A hook that blocks is worse than a hook that misses, so every hook prints a visible note and lets the work go on after an internal error: the context, compaction, and autosave hooks exit zero, and the two PreToolUse guards exit one, which Claude Code shows as a notice without blocking. Only a real violation found by a guard exits two and blocks the call. The deterministic backstop is node scripts/work.mjs check, which fails on the same conditions.

Reads are paranoid where a hash matters. The documentation reader refuses symbolic links, reparse points, and multiply linked files, and re-checks file identity after reading. A fingerprint that can be fooled is worse than no fingerprint. The root is resolved with the native realpath so a short-name temporary directory does not look like a reparse point.

Line endings are normalized for text. .gitattributes checks every text file out with LF on every platform, and the fingerprints normalize line endings anyway, so a page an editor saved with CRLF is not marked stale. Archived bytes are the exception: they are pinned exactly and kept out of Git's conversion.

Cooperative-host threat model. These guards catch the accidental lapse. They are not access control, and a recorded, expiring override exists for a real emergency.
